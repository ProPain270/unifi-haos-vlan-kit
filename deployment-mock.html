Home Assistant OS — placement & integration

◆
Lives on VLAN 50 (Servers) — static IP (e.g. 10.10.50.10). HAOS as a VM (Proxmox/mini-PC) or dedicated appliance.
◆
Cross-VLAN device discovery — enable UniFi mDNS/Multicast DNS reflection on Trusted + IoT + Servers so HA auto-discovers IoT (HomeKit, Chromecast, ESPHome, printers) across the VLAN boundary. This is the #1 thing clients get wrong.
◆
Remote access without port-forwarding — Tailscale add-on (your model) or Nabu Casa. No inbound WAN holes.
◆
UniFi ↔ HA — UniFi Network integration in HA for presence, client tracking, and VLAN-aware automations; UniFi Protect integration for cameras on VLAN 30.
◆
Resilience — nightly HA backups to NAS/offsite; document restore. Hand the client a one-pager.

Deployment runbook — remote-repeatable

1
Pre-stage. Adopt UCG-Max + switch + APs to the UniFi console (cloud or self-host). Firmware update. Set site name + admin + backup.
2
Create the 6 networks/VLANs from the table (IDs, subnets, DHCP ranges, DNS). Template this.
3
Firewall rules per the matrix: allow established/related, then per-VLAN isolation + the HA-is-the-only-initiator exceptions.
4
Wi-Fi — create the 3 SSIDs → VLANs; apply AP group to all 7; tune min-RSSI/band steering.
5
Switch — apply the named port profiles; label ports; verify PoE budget for 7 APs + cameras.
6
mDNS reflection on Trusted/IoT/Servers.
7
Deploy HAOS on VLAN 50, static IP, restore baseline config/HACS, Tailscale, integrations.
8
Verify — device on each VLAN pulls correct DHCP; Guest can't see internal; IoT can't initiate to Trusted; HA discovers + controls IoT; cameras have no WAN. Screenshot for the client.
9
Handover + monitoring — client one-pager, remote-support access (Tailscale/UniFi), and an ongoing check-in cadence (this lead wants a relationship, not a one-off).
Make steps 2–6 a UniFi site backup template you restore onto each new console — then a deploy is "restore template → re-adopt hardware → tweak subnets → deploy HAOS." That's the repeatable remote product.
